# 3단계: 공격적 B / 수비적 C와 실제 1대1 플레이

stage3.py/execution.py/opponents.py에 구현했다. 실제 Ollama를 사용하는 A의 행동과 칩 성과를 평가한다.
공통 경계·자료 격리·로그는 [README.md](README.md)를 따른다.

## 1. 테이블과 시행 수

- 대전 1: Table(['A', 'B']). B는 공격적인 고정 정책.
- 대전 2: Table(['A', 'C']). C는 수비적인 고정 정책.
- 두 대전 모두 인간 없음. B와 C가 동시에 앉는 3인 게임이 아니다.
- 각 상대에 대해 30개의 독립 라운드를 control/both로 대응 실행한다. 총 120라운드.
- 추가 네 조건 비교는 별도 실행 ID로 명시한 확장 실험(240라운드)이다.

기본 한 시행은 **배분부터 공개·정산까지 한 라운드**다. 매 시행 Table/초기 칩/과거 자료를
복원하고 다음 시행으로 칩이나 메모를 이월하지 않는다. 따라서 30회 모두 같은 시작 조건으로
정보 유무를 비교할 수 있다. 한 게임을 30라운드 이어서 하는 학습/적응 실험과 구분한다.

control에는 현재 판세/현재 라운드 공개 대화를 제공하고 검색/메모 입력을 끈다.
both에는 같은 판세와 사전 경험 뱅크/메모를 제공한다. both에서 현재 라운드 중 발생한
메모 갱신은 이후 판단에 읽힐 수 있지만 라운드가 끝나면 다음 비교 시행에는 이월하지 않는다.
이 차이는 라운드 내 기억 유지 효과까지 포함한 both 조건의 일부다.

## 2. 고정 정책 상대 계약

opponents.py의 FixedPolicy 두 스타일은 `ainvoke(state) -> {'decision': AgentDecision.model_dump()}`를 구현해
RoundRunner에 직접 주입한다. 별도의 LLM 그래프를 구성할 필요가 없다.
입력은 runner가 준 Observation/event/force_bet뿐이며 Table 객체나 숨은 전체 카드를 전달하지 않는다.
둘 다 검색 호출/메모 읽기/메모 쓰기/LLM 호출은 0회여야 한다. 모델 이름이나 메모 내용을 보고
조건을 추측해 정책을 바꾸지 않는다. 기본 fake 체크/콜 정책을 그대로 사용하지 않는다.

상대 자신의 카드는 알 수 없다. 자기 카드로 승률을 계산하거나 평가용 정답 배분을 읽지 않는다.
현재 관찰의 A 카드와 공개 베팅/대화, 고정 정책용 난수만 사용한다.
필요한 비전략적 카운터(예: 본인의 레이즈 수)는 공개 베팅 로그에서 계산하거나
라운드 범위의 작은 정책 상태로 보관한다. 자연어 개인 메모나 라운드 간 학습으로 확장하지 않는다.

두 정책의 공통 처리:

- revealed이면 speech=unavailable, bet=null, 빈 memory_updates로 즉시 반환한다.
- 최소 게임 발언이 남아 있고 can_speak=true이면 한 번 발언한다. 최소 발언 전에는 베팅하지 않는다.
- 이후 새 게임 발언은 기본적으로 하지 않는다. 최소 발언 충족 후 가능한 경우 silent,
  그렇지 않으면 unavailable을 반환해 runner와 발언 제한 계약을 지킨다.
- allowed_bets가 없으면 bet=null. 베팅 차례가 오면 반드시 합법적인 행동을 고른다.
- 아래 정책 확률은 해당 분기의 난수 u 하나로 결정하고 버전/seed를 기록한다.
- 레이즈 불가/자기 레이즈 상한 도달 시 raise 확률을 check 또는 call에 합친다.

### 공격적 B의 정책 v1

| 상황 | 행동 |
|---|---|
| check 가능 | u<0.70이면 raise, 나머지 check |
| call 필요 | u<0.50이면 raise, 0.50≤u<0.90이면 call, 나머지 fold |
| 레이즈 규모 | large(+4) → medium(+2) → small(+1) 중 사용 가능한 첫 크기 |
| 자기 레이즈 상한 | 한 라운드 2회. 이후에는 위 fallback 적용 |

첫 발언은 고정 주장 “네 카드는 10 이하야.”로 둔다. 관찰한 A 카드가 J 이상일 때도 같은
주장을 하므로 과거 공개 결과에서 거짓 주장이 확인될 수 있다. 이 표현은 상대가 보는
A 카드에 대한 주장이지 B 자신의 카드에 대한 지식이 아니다.

### 수비적 C의 정책 v1

| 상황 | 행동 |
|---|---|
| check 가능 | u<0.10이고 small 사용 가능하면 small raise, 나머지 check |
| call 필요, 관찰한 A 카드가 J 이상 | u<0.20이면 call, 나머지 fold |
| call 필요, 관찰한 A 카드가 10 이하 | u<0.60이면 call, 나머지 fold |
| 자기 레이즈 상한 | 한 라운드 1회. 맞레이즈는 하지 않음 |

첫 발언은 A의 관찰 카드에 따라 “네 카드는 J 이상이야.” 또는 “네 카드는 10 이하야.”로 둔다.
주장은 관찰과 일치한다. 이 구분은 수치 구간일 뿐, 2와 A의 순환 규칙까지 고려한 최적 전략이 아니다.
이 정책은 공격/수비 차이를 재현하는 실험 상대이며 강한 포커 전략이라고 주장하지 않는다.

## 3. 과거 자료와 시드

본 평가와 다른 seed로 같은 B/C 정책을 실행한 완료 라운드에서 경험 뱅크를 만든다.
준비 라운드의 A는 고정 기준 정책으로 두고, 해당 대전의 공개 아카이브만 적재한다.
준비 로그·사용 정책 버전·공개 진위 판정·메모 요약의 출처를 보존한다.
폴드로 A 카드가 미공개인 과거 판은 B 주장 진위 불명으로 둔다. 불명 사례를 거짓으로 세지 않는다.
동일한 뱅크를 매 독립 라운드 시작 시 복원하고 20개 FIFO/실제 색인 자료를 검증한다.
평가가 끝난 현재 라운드의 archive는 저장하되, 다음 시행의 입력 경험으로 자동 적재하지 않는다.

대응 키는 (상대 정책, case_id, 카드 배분, 시작 좌석, 정책 seed)다.
상대별 30개 중 15개는 A 선행, 15개는 상대 선행으로 사전에 정한다.
동일 사례의 control/both는 같은 ID별 카드 매핑을 start_round(cards=...)에 전달한다.
Table 생성 순서가 달라도 seed 하나로 같은 카드가 같은 사람에게 갈 것이라 가정하지 않는다.

상대 정책의 난수는 모델 호출 순서나 공유 random 전역 상태를 쓰지 않고
(정책 seed, case_id, 해당 상대의 베팅 판단 순번)으로 결정한다. 조건에 따라 게임 경로가
달라지면 실제 판단 순번/행동 수도 달라질 수 있으므로 이후의 모든 사건이 같다고 주장하지 않는다.
조건 실행 순서는 공통 명세처럼 섞되 pairing은 유지한다.

## 4. 엔진 실행 흐름

1. 사례별 격리 경로와 GameConfig를 준비한다. 초기 칩 30, 참가비 2 및 목표치는 공통 config에서 읽는다.
2. Table을 만들고 start_round(cards=...)로 사전 배분한다. 칩/차례를 직접 수정하지 않는다.
3. A에는 기존 build_graph(ExperimentPokerLLM + PlayerLLM)를, 상대에는 고정 정책 객체를 주입한다.
4. RoundRunner.run_round()를 실행한다. 이미 dialogue 상태의 Table을 runner가 이어서 처리하는
   기존 동작을 사용한다. 생산 코드의 큐/동시성/베팅 유효성 검사를 그대로 통과한다.
5. on_event로 확정 사건을 수집하고, 관찰 래퍼로 A의 입력/출력/메모/usage/시간을 추가 수집한다.
6. 라운드 정산·회고 완료와 칩 보존을 검사하고 원본 아카이브/실험 로그를 보관한다.
7. MCP와 task를 정리하고 다음 조건/사례를 fresh 환경에서 실행한다.

별도 step loop나 포커 엔진을 작성하지 않는다. 승자와 판돈을 실험 코드에서 다시 계산해
엔진 결과를 대체하지 않는다. 제한 시간/runner_max_decisions/실패 시 자동 행동은 기존 규칙을
유지하고 오류 기록을 남긴다. 모든 동작은 UI 없이 엔진/API 객체를 직접 호출한다.

## 5. 지표와 결과 파일

| 지표 | 정의 |
|---|---|
| 주 지표 | A의 종료 칩 − 참가비 차감 전 초기 칩. 사례별 both − control 대응 차이도 보고 |
| 보조 승률 | 공개·정산까지 완료한 라운드 중 A 승리 비율. 독립 라운드의 결과임을 명시 |
| 행동 | check/call/fold/raise 수, 실제 raise 증가량, A/B/C별 별도 집계 |
| 근거 | A 발언·메모에 과거 사실과 현재 행동이 연결되는지. 1단계와 같은 기준 |
| 안정성/비용 | 모델/임베딩 호출 수, 재시도, 거절/보류/rejudge, 자동 대체, 시간 초과, 라운드 및 판단 지연 |

두 명의 중복 없는 카드에서는 순환 무승부가 발생하지 않는 것이 현재 규칙의 정상 동작이다.
draw가 나오면 데이터/엔진 상태를 확인한다. 판돈 지급 뒤 A+상대의 칩 합이 초기 총액과
일치하는지도 검사한다. 승리 횟수 증가와 칩 수익 증가가 다를 수 있으므로 둘을 합치지 않는다.

보고서는 B와 C 결과를 따로 내고, 필요하면 동일 가중치의 전체 요약을 추가한다.
원본 결정/확정 사건/정산/근거 평가를 연결해 “왜 콜 대신 레이즈했는가”를 사례로 확인한다.
준비된 자료와 다른 상대 정책 버전이 실행됐거나 자료가 누출되면 해당 실행을 유효 비교로 세지 않는다.

## 6. 해석 범위와 후속 확장

기본 실험이 검증하는 것은 **고정된 과거 자료를 제공했을 때 두 고정 상대에 대한 한 라운드
플레이가 어떻게 달라지는가**다. 일반적인 상대, 인간 상대, 모델끼리의 협상, 장기 학습,
전체 게임 우승률의 개선까지 일반화하지 않는다.

연속 게임 적응을 보고 싶다면 별도 단계로 여러 게임을 실행한다. 칩/메모/FIFO 이월,
조기 탈락/목표 달성, 게임별 최대 라운드를 사전에 정하고 독립 표본은 개별 결정이 아니라
게임/에피소드로 센다. 그때의 30라운드를 현재의 30개 독립 평가와 섞지 않는다.
