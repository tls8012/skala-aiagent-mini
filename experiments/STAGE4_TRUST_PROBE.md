# 실험 4: 서로 다른 10개 배패에서 과거 주장의 진위 반전

## 목적과 기존 단계와의 차이

서로 다른 배패 10개 각각에서 판세를 고정하고 과거 자료의 방향만 바꿔 다음 연결을 진단한다.

1. 과거 발언의 화자/대상과 공개 카드의 소유자를 정확히 읽는가?
2. 주장이 공개 결과와 일치했는지에 따라 상대 신뢰도 평가가 달라지는가?
3. 그 평가가 개인 메모와 실제 베팅 선택에 연결되는가?

1단계는 여러 상황에서 관련/무관 정보에 대한 반응을, 2단계는 검색/메모 채널을,
3단계는 고정 정책 상대와 완료 라운드의 칩 성과를 비교한다. 4단계는 그 원인을 좁히기 위한
반사실 진단이다. 특히 동일 문장이 모두 맞았던 과거와 모두 틀렸던 과거를 직접 대조한다.
실행 경로는 1단계와 공유하지만 새로운 실험 번호로 분리해 결과를 섞지 않는다.

## 배패별 고정 장면과 세 조건

평가자는 A다. 엔진 설정은 초기 칩 30, 참가비 2, 최소 게임 발언 1회로 고정한다.
모델/추론 설정/메모 길이/통신 설정은 기존 GameConfig를 사용한다.

- A가 관찰하는 B의 카드는 아래 배패 표에 따른다. 현재 A의 카드는 모델에 공개하지 않는다.
- A의 준비 발언 후 B가 A를 대상으로 “네 카드는 10 이하야.”라고 말한다.
- B가 4칩을 레이즈한 직후, 팟은 8, A의 콜 비용은 4다.
- A 차례의 허용 행동은 call/raise/fold다. 모든 조건에서 같은 스키마와
  스탠다드 행동 지시문을 쓰고 force_bet=true로 한 번의 결정을 요구한다.
- 모델의 추가 공개 발언과 개인 메모 갱신도 기존 계약대로 허용한다.

| 사례 | A 비공개 배패(평가자용) | B 관찰 카드 | 구성 의도 |
|---|---|---|---|
| 01 | 10H | 9C | 첫 실행과 같은 배패 |
| 02 | AH | 2S | 2가 A를 이기는 예외 |
| 03 | 2C | AH | 같은 예외의 반대 배치 |
| 04 | KS | KD | 높은 같은 숫자, 문양 차이 |
| 05 | 9S | 10C | 주장 경계값 10인 상대 |
| 06 | QD | JH | 상대가 주장 범위보다 높음 |
| 07 | JH | QS | 높은 상대 카드 |
| 08 | 4C | 3D | 낮은 상대 카드 |
| 09 | 5S | 5H | 낮은 같은 숫자, 문양 차이 |
| 10 | 6D | 7C | 중간 상대 카드 |

숨겨진 A 카드만 바꾸면 A의 관찰 입력은 같아지므로 B 카드도 배패마다 다르게 했다.
A의 실제 카드는 manifest.protocol.deals와 trials.deal에 평가자용으로 기록하며 프롬프트에는
넣지 않는다. 위 배패의 승패 관계를 모델이 미리 알 수 있다는 뜻은 아니다. 두 명의 배패로
2/A의 예외를 포함하지만 세 명 이상에서의 순환 무승부를 시험하지는 않는다.

| 조건 | 직접 제공하는 공개 과거 자료 | 평가자용 정답 |
|---|---|---|
| no_information | 없음 | 평가할 과거 주장 없음 |
| trustworthy_history | B의 같은 주장 3건과 해당 라운드 A 카드 3S/4S/5S | 일치 3, 불일치 0 |
| deceptive_history | B의 같은 주장 3건과 해당 라운드 A 카드 JS/QS/KS | 일치 0, 불일치 3 |

과거 B 카드는 모두 9C다. 발언의 target=A를 명시하고, 과거 화자·대상·발언·베팅·
요청 ID·경험 ID는 두 자료 조건에서 같게 한다. A의 공개 카드와 그에 따른 정산 결과가 달라진다.
과거 기록은 별도 Table에서 발언과 체크/체크를 실제 접수하고 공개까지 완료해 생성한다.
임의로 winner와 카드를 조합한 가짜 정산 JSON을 만들지 않는다.

모델은 과거 자료를 기존 RAG의 발언 청크 + round_context.result 형식으로 받는다.
조건 이름, 일치 횟수, 평가용 정답, 신뢰도 요약은 모델에 주지 않는다.
현재 observation/event/game_id/request_id는 같은 배패의 세 조건에서 동일하다.
system 프롬프트와 조건별 과거 자료는 배패가 달라져도 동일하게 유지한다.
배패별·조건별 data_dir는 분리하고, 준비된 단기/중기/장기 메모는 모두 비워 입력을 차단한다.
출력 메모는 remember → write_memo → read-back 경로로 실제 저장해 확인한다.

검색·임베딩·Chroma 순위와 사전 메모의 영향은 이번 진단에서 제외한다.
OpenAI 판단을 쓰면 임베딩용 Ollama를 띄울 필요가 없다. MCP는 기존 파일 메모를 위해 사용한다.
Ollama 판단을 선택하면 해당 판단 모델을 제공하는 Ollama는 필요하다.

## 실행량과 실행법

```sh
# 배선 검사: 실제 모델/임베딩 호출 없음
.venv/bin/python -m experiments.run --stage 4 --cases 1 --backend fake

# config의 백엔드/모델로 전체 실행: 10개 배패 × 3조건 = 30개 판단
.venv/bin/python -m experiments.run --stage 4

# 앞의 배패 3개만 확인: 3개 배패 × 3조건 = 9개 판단
.venv/bin/python -m experiments.run --stage 4 --cases 3

# 조건 두 개만 직접 비교: 10개 배패 × 2조건 = 20개 판단
.venv/bin/python -m experiments.run --stage 4 --cases 10 \
  --conditions trustworthy_history deceptive_history
```

4단계는 cases=1..10이며 기본값은 10, 기본 세 조건이면 총 30개 판단이다.
**cases는 서로 다른 배패 수다. 같은 장면의 반복 수나 완료 라운드 수가 아니다.**
cases=N은 고정된 표의 앞 N개 배패를 선택한다. 1~2단계 기본값은 30이고,
3단계도 같은 배패 표를 사용하며 기본값 10으로 실제 라운드를 비교한다.
각 배패·조건은 새 그래프/격리 저장소에서 시작한다. 조건 실행 순서는 seed로 섞고,
같은 조건의 과거 자료는 배패마다 다시 샘플링하지 않는다. seed는 조건 순서를 제어하며
공급자 모델의 생성 seed나 응답의 완전한 결정성을 보장하지 않는다.

실행은 기존 graph → PokerLLM → PlayerLLM → llm_controller → 선택된 백엔드를 거친다.
한 그래프 호출의 제안을 Table.apply_decision으로 접수한 뒤 멈춘다. 검증 재시도가 있으면
모든 추가 호출을 기록한다. 다음 상대 행동·RoundRunner·공개 후 회고는 실행하지 않는다.
따라서 이 실험은 라운드 승률이나 최종 칩 이득을 산출하지 않는다.

## 로그와 평가

기존 manifest/model_calls/decisions/research/tools/contexts/trials와 시간/토큰 로그를 유지한다.
manifest.protocol(version=2, unit=distinct_deal)에 배패 목록, 직접 자료 주입, 메모 입력 차단과
승률 미평가를 명시한다. trials의 input_hash는 같은 배패의 세 조건에서 같고 배패 사이에는
달라야 한다. evidence_hash는 같은 자료 조건이면 배패가 달라져도 같다.
최종 원문 확인은 model_calls의 system/user/schema를 기준으로 한다.

- fixture-provenance.json: 각 과거 엔진 라운드 원본과 해시.
- data/<trial_id>/ground_truth.json 및 trials.ground_truth: 과거 발언의 화자 B,
  대상 A, A 카드, B 카드, 진위, 출처 ID. 평가용으로만 저장한다.
- stage4_review.csv: 실제 발언/메모/선택과 평가용 일치 횟수·A 카드 목록을 나란히 제공한다.
  extraction_correct, trust_assessment, action_link_supported, notes는 사람이 채운다.
  보고서를 다시 생성해도 작성한 평가는 덮어쓰지 않는다.
- summary: 조건별 행동 분포와 세 대응 비교를 낸다. no_information 대비 각 자료 조건,
  trustworthy_history 대비 deceptive_history를 비교한다. 단순 행동 종류뿐 아니라
  레이즈의 실제 증가량 차이도 기존 기준으로 비교한다. 배패별 행동 표도 함께 제공한다.
  대응 비교는 같은 case_id 안에서만 수행한다.

다음 순서로 수동 평가한다. 숨은 추론이나 정해진 문장 출력을 요구하지 않는다.

| 단계 | 확인할 내용 | 미표기/오류 처리 |
|---|---|---|
| 자료 해석 | B의 주장이 A 카드에 대한 것임을 구분하고 공개 결과를 올바르게 읽었는가 | 집계를 안 썼으면 unreported; 잘못된 집계와 구분 |
| 신뢰도 | 제공된 이력에 맞는 관찰을 근거로 신뢰/불신/유보를 설명하는가 | 단어 언급만으로 통과 처리하지 않음 |
| 행동 연결 | 실제 자료 → 현재 주장 평가 → 콜/폴드/레이즈 계획이 메모에 연결되는가 | 행동 변화와 올바른 근거를 따로 평가 |

trust_assessment에는 예를 들어 higher/lower/uncertain/unreported/incorrect를 기록하고,
extraction_correct와 action_link_supported는 yes/no/unreported/not_applicable로 구분한다.
기본 no_information의 자료 해석은 not_applicable이다. 공란은 미평가이며 성공/실패로 세지 않는다.
숫자를 직접 세지 않았더라도 명시된 관찰의 정확성은 평가할 수 있으나, 정확한 3건 집계 능력을
입증한 것으로 기록하지 않는다. 실제 접수 여부는 trials.valid/applied와 decisions의 applied를 본다.

## 해석 범위와 다음 분기

- 공개 자료를 틀리게 읽으면 입력 표현/모델의 기본 해석부터 점검한다.
- 자료는 맞게 읽고 신뢰도 평가는 바뀌는데 행동이 같으면 현재 상황의 비용·선택 정책을 점검한다.
- 행동만 바뀌고 근거가 틀리면 올바른 정보 활용의 증거로 삼지 않는다.
- 직접 자료 주입에서 근거와 행동이 연결되면 다음으로 동일 자료의 실제 검색 경로를 비교한다.
  그때에만 검색 품질이나 사전 메모 요인을 추가한다.
- 세 건의 합성 이력은 현재 주장의 참/거짓을 보장하지 않는다. “과거 전부 거짓이므로 이번에도
  반드시 반대”라는 단정은 과도한 일반화다. 특정 행동을 유일한 정답으로 자동 채점하지 않는다.
- 동일 행동도 합리적일 수 있다. 일부 배패의 무변화만으로 정보가 무가치하거나 현실에서
  정보를 안 쓰는 편이 더 좋다고 결론내리지 않는다. 배패별 차이와 전체 분포를 함께 본다.
