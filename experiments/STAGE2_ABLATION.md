# 2단계: control / 검색만 / 메모만 / 둘 다

stage2.py/execution.py/backends.py에 구현했다. 판세를 고정한 상태에서 검색과 메모의 효과를 분리한다.
공통 경계·자료 준비·로그는 [README.md](README.md), 판단 절차는 [1단계](STAGE1_INFORMATION.md)를 따른다.

## 1. 조건과 시행 수

30개 고정 상황을 네 조건에 대응시킨다. 총 120회 그래프 평가다.
1단계와 같은 유형 구성을 쓰되 별도 카드 배분/상황 ID를 미리 정해 둔다.
1단계 결과를 보고 효과가 컸던 상황만 골라 구성하지 않는다.

| 조건 | 현재 판세/현재 라운드 대화 | 과거 검색 | round/game/long 메모 입력 |
|---|---|---|---|
| control | 동일하게 제공 | 꺼짐 | 모두 비움 |
| search_only | 동일하게 제공 | 실제 MCP/Chroma | 모두 비움 |
| memo_only | 동일하게 제공 | 꺼짐 | 사전 고정 메모 |
| both | 동일하게 제공 | 실제 MCP/Chroma | 같은 사전 고정 메모 |

control의 “판세 이외 정보 없음”은 과거 경험과 지속 메모가 없다는 뜻이다.
현재 라운드 대화를 control에서만 삭제하거나 최소 발언/콜 비용 정보를 줄이지 않는다.
search_only와 both는 동일한 경험 뱅크를, memo_only와 both는 동일한 메모를 사용한다.
메모는 그 경험 뱅크의 공개 사실을 요약한 것으로 준비해 두 경로의 정보 내용 차이를 줄인다.
원본 기록과 요약의 표현/분량 차이는 남으므로 이를 완전히 동등한 정보량 실험이라고 부르지 않는다.

## 2. 실제 검색·메모 준비

1. 사례마다 과거 엔진 라운드에서 만든 공개 경험 뱅크를 격리된 MCP 저장소에 적재한다.
2. 기본 seed_rounds 자동 생성 여부와 실제 유지된 경험 ID/해시를 확인한다.
3. Chroma 색인을 준비하고 memory_status의 indexing=false/error 없음과 probe 검색을 확인한다.
4. round/game/long 메모를 기존 write_memo로 저장한다. 상한을 지키며 source→memo 대응표는
   평가 파일에 둔다. 모델에게는 허용된 메모 텍스트만 제공한다.
5. 조건별로 같은 엔진 상태를 만들고 그래프를 실행한다. 실제 연구 질의는 기존 research가 생성한다.
6. 모델에 최종 첨부된 메모와 실제 검색 matches를 보존한다. 메모 off의 쓰기는 감사 로그에만 남긴다.

한 결정이 끝난 뒤 새 판단을 이어서 호출하지 않는다. 조건마다 fresh Table/data_dir를 사용한다.
기존 research 캐시도 조건 사이에 재사용하지 않는다. 그래프 검증 재시도 중 읽히는 메모/검색
내용은 기록해 첫 호출 이후 정보가 달라졌는지 확인한다.

## 3. 무엇을 비교하는가

| 대비 | 해석 목적 |
|---|---|
| search_only − control | 메모 입력 없이 검색을 켠 효과 |
| memo_only − control | 검색 없이 개인 메모를 켠 효과 |
| both − search_only | 검색이 있을 때 메모를 더한 변화 |
| both − memo_only | 메모가 있을 때 검색을 더한 변화 |

1단계의 행동 signature/근거 점수/오류/지연/호출 수를 그대로 사용한다.
행동 종류는 수치적 우열로 빼지 않고 대응 전환표(check→raise, call→fold 등)로 표시한다.
근거 점수와 지연 등 수치 지표는 사례별 대응 차이를 함께 낸다. 이 단계만으로 수익 개선을 주장하지 않는다.

검색 사용은 다음 세 층으로 기록한다.

- 가용성: 실제 검색 호출 여부와 ready/indexing/unavailable/skipped.
- 관련성: 원하는 상대·사건이 있는지, 주장을 검증하는 공개 결과까지 반환됐는지.
- 반응: 반환된 정보와 일치하는 발언/메모 근거, 실제 접수 행동 변화가 있는지.

“ready+관련 청크 반환인데 행동 변화 없음”과 “검색 자료가 애초에 없음”은 서로 다른 결과다.
현재 검색은 사건 청크 상위 결과를 주므로 발언만 나오고 결과 청크는 없을 수 있다.
그때 모델이 “확인된 블러프”라고 단정하면 출처를 읽었다는 이유만으로 사실성 성공으로 세지 않는다.

## 4. 결과 형식과 판단

30행의 대응표에 네 조건의 행동/실제 증가량/발언 근거/메모 근거/검색 상태/유효 여부를 배치한다.
조건별 행동 분포, 각 대비의 변화 건수, 무근거 과거 사실 언급, 소수 표본의 과도한 일반화,
평균·중앙 지연과 모델/임베딩 호출 수를 요약한다.

기억이 있는 조건에서만 출처에 맞는 반응이 늘면 정보 경로의 효과를 관찰한 것이다.
둘 다가 항상 더 좋아야 한다는 합격 기준은 두지 않는다. 중복 자료/오래된 메모/검색 누락에 의한
역효과도 기록하고, 좋은 예문만 골라 “검색+메모가 우수하다”고 결론 내리지 않는다.
3단계의 기본 control/both 비교가 효과가 없더라도 결과를 그대로 남긴다.
